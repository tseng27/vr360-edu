學生不能呼叫教師指令 / 不能改資料表 / 不能在頻道上廣播（只能送 presence）、非成員讀不到房間與頻道、
序號遞增與資料庫廣播、晚到學生讀到最新狀態、重新整理讀快照、加入節流（第 15 次被擋）、結束後代碼失效、
24 小時後清除匿名資料、未登入（anon）不能呼叫任何 RPC。

端到端測試涵蓋：建立教室與 QR Code、錯誤代碼訊息、兩位學生同步切到場景 B、第三位晚到直接看到 B、
老師名單只顯示暱稱、「看這裡」提示與邊緣箭頭、提示期間學生仍可自由轉頭、學生自己按「前往老師指定方向」、
解說卡同步且 HTML 以純文字顯示、自由探索互不影響、切回跟隨重新對齊、學生端忽略偽造 / 重播 / 格式錯誤的事件、
重新整理讀到最新狀態、不支援 WebXR 時沒有 VR 按鈕、10 位學生同時同步、結束課堂與代碼失效。

10 個分頁時，從老師點擊到最後一位學生狀態更新約 0.1–2.4 秒。這是**同一台雲端主機**同時渲染 11 個 WebGL 分頁的數字，
受 CPU 限制，不代表真實網路延遲，也不能拿來推論 Supabase 或校內 Wi-Fi 的表現。

## 尚未驗證（不可視為通過）

- 連上真正的 Supabase 專案：匿名登入、Realtime 私有頻道授權、presence、`realtime.send` 廣播、Storage 上傳。
  資料庫邏輯是在模擬環境測的，真正的 Realtime 伺服器行為還沒跑過。
- 任何實體手機、平板、VR 頭盔；陀螺儀；iOS 權限流程。
- 跨裝置、跨網路同步；19 人校內 Wi-Fi 負載；斷網後重連（只測了重新整理）。
- GitHub Pages 子路徑部署（見 README「部署」）。

## 已知限制

- Mock 模式沒有安全性：同瀏覽器的分頁可以偽造「老師」事件。真正的權限控管只在 Supabase 模式。
- 老師操作失敗時不會留下節流紀錄（交易回滾），老師端節流較寬鬆（每分鐘 120 次）。
- 匿名帳號可被大量建立，請在 Supabase 開啟 CAPTCHA / Auth rate limit。
- 加入代碼 6 碼（約 8.9 億組合），搭配每帳號 10 分鐘 15 次節流與有效期限；不是唯一的安全措施。
- 從「我的 360 專案」匯入場景只在 mock 模式可用（圖片在本機 IndexedDB）；Supabase 模式請改用上傳。
- 沒有離線快取（Service Worker），避免學生看到過期狀態。
